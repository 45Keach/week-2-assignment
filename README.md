# My Budget Tracker — Week 2 Visual Design Challenge

A polished CSS-focused update of the existing Budget Tracker. This submission keeps the existing HTML structure and functionality while improving the visual design with a cohesive color palette, Google Fonts, form styling, table styling, and intentional use of the CSS box model.

## What I built

I continued the existing Budget Tracker rather than starting a new project. The main goal for Week 2 was to make the application cleaner, more readable, and more professional without adding new HTML structure or JavaScript functionality.

### Design improvements

- **Intentional color palette:** A small navy, blue, mint, orange, slate, purple, and teal palette is used consistently across the navigation, headings, cards, buttons, form controls, table, and supporting sections.
- **Typography:** Google Fonts are loaded directly in `style.css`. **Plus Jakarta Sans** is used for headings and **DM Sans** is used for body text, labels, controls, and table content.
- **Form styling:** Inputs and the category select have consistent padding, borders, rounded corners, focus states, and readable typography. The Add Expense button uses the same blue accent as other key interface elements.
- **Table styling:** The expense table has a clear navy header, padded cells, borders, rounded corners, alternating row backgrounds, and a subtle hover state.
- **CSS Box Model:** The page sections use margin for separation, padding for internal spacing, borders for definition, border-radius for softer edges, and shadows for visual depth.
- **Responsive design:** The existing layout remains usable on smaller screens, including a horizontally scrollable expense table and stacked service cards.

## Project files

- `index.html` — Existing page structure containing the navigation, Budget Tracker heading, Add Expense form, expense table, help section, video, services, contact section, and footer.
- `style.css` — Complete visual design layer, including the color variables, Google Fonts, cards, form controls, button states, table styling, spacing, borders, shadows, and responsive rules.
- `README.md` — Documentation explaining the project and Week 2 design improvements.

## Rubric checklist

### 1. Intentional Color Palette — 25%

- Consistent navy and blue brand colors.
- Soft supporting backgrounds for individual sections.
- Matching button and table-header treatment.
- CSS custom properties keep the palette consistent and easy to maintain.

### 2. Typography — 20%

- Plus Jakarta Sans for headings and important labels.
- DM Sans for body copy and controls.
- Clear font sizes, weights, and line heights create visual hierarchy.

### 3. Table and Form Styling — 30%

- Form controls have padding, borders, rounded corners, and focus feedback.
- Button has cohesive color, spacing, rounded corners, and hover feedback.
- Table has a styled header, cell spacing, borders, alternating rows, and row hover feedback.

### 4. CSS Box Model — 25%

- Page sections have intentional margin and padding.
- Borders distinguish cards and controls.
- Border-radius creates a modern card appearance.
- Box shadows add separation from the page background.
- The page heading, Add Expense form, and Expense Table are visually distinct card-style sections.

## Functionality note

The Add Expense button remains intentionally unconnected to JavaScript. This preserves the existing project functionality and follows the Week 2 requirement to focus on CSS visual design rather than adding new functionality.
